# Аудит границ чанков транскрибации

## Что проверено статически

- `AudioCapture.processLongFileInChunks` и `retranscribeNote` делили запись на фиксированные 25-секундные окна без overlap и без учета речи у границы.
- Локальный архив на момент полного аудита: 1 070 элементов истории, 1 056 уникальных WAV, 211 уникальных записей длиннее 25 секунд. В папке 1 054 WAV (~584 MB); это общий размер архива, ничего не отправлялось в сеть.
- Это не доказывает, что именно на стыках были ошибки: сохранённые результаты не содержат эталонной расшифровки.


JSON-отчёт содержит распознанную пользовательскую речь: оставлять локально, не коммитить и не прикладывать к issue без проверки приватности.

По умолчанию скрипт использует локальную историю, сохранённые WAV и GigaAM `transcribe-cli` из `/Applications/Golosok.app`. Ничего не передаётся в сеть. На каждой прежней границе он сравнивает отдельные полные окна слева/справа (до 4 секунд) с цельным контекстным окном ±4 секунды; повторяет split halves три раза на каждой десятой границе; дополнительно распознаёт 2-секундные core-фрагменты. Из 319 номинальных границ 41 исключена из-за недостатка правого контекста (не менее 2 секунд), осталось 278.

### Как трактовать результат

`split_continuous_distance` — нормализованное word-edit расстояние между склейкой отдельных left/right прогонов и прогоном цельного контекстного окна. Это мера чувствительности к разрезу/контексту, не WER. `split_repeat_distance` оценивает разброс повторных split-прогонов. Доверительные интервалы получены cluster bootstrap по записи; знак-тест применён к 23 контрольным записям и является exploratory.

### Полный результат (278 границ)

Полный прогон занял **284,82 секунды**. Единица кластеризации — запись, чтобы границы одного длинного WAV не считались независимыми.

| Показатель | Результат |
|---|---:|
| Границы с достаточным контекстом | 278 / 319 |
| Записи, представленные в сравнении | 172 |
| Среднее split-vs-whole нормализованное расстояние | 0,157 (95% cluster-bootstrap CI 0,115–0,169) |
| Расстояние >0,1 | 129/278 = 46,4% (CI 39,7–53,5%) |
| Расстояние >0,2 | 79/278 = 28,4% (CI 18,7–30,8%) |
| Расстояние >0,3 | 50/278 = 18,0% (CI 8,8–18,4%) |
| Расстояние >0,5 | 15/278 = 5,4% (CI 1,4–6,3%) |

Для более содержательной речевой подвыборки исключены случаи, когда одна из половин дала меньше двух слов или цельное окно меньше четырёх слов: осталось 179/278 сравнений (128 записей). Среднее расстояние — **0,133**; пороги >0,2: **24,0%**, >0,3: **11,2%**, >0,5: **2,2%**. В cluster-bootstrap интервалы для этих долей: >0,2 — 13,3–26,6%; >0,3 — 3,4–12,0%; >0,5 — 0–2,6%.

На контрольных повторах (24 границы, 23 записи) split-vs-whole расстояние в среднем превышало повторный разброс на **0,132** (95% cluster-bootstrap CI 0,073–0,197). Знак-тест: 12 из 12 ненулевых кластерных разниц положительные, одностороннее p=0,00024. Это свидетельствует о систематической чувствительности к контексту/разрезанию в тестовом сравнении, но контрольная подвыборка невелика и неслучайна во времени (каждая десятая граница), поэтому p-value нельзя интерпретировать как частоту пользовательских ошибок.

**Искажения-кандидаты** в полном отчёте включают:
- короткие междометия/однословные края («угу», «да»), где относительное расстояние искусственно велико — они исключены из речевой sensitivity-подвыборки;
- длинные фразы, где halves теряют продолжение, восстанавливаемое цельным окном (например, запись `1F9B3D9E-C109-416A-B59F-DFD50A952567`, границы 100–150 с);
- редкие IT-термины, которые искажаются и в split, и в цельном окне (например, `rotextermext`), это общий ASR/hotword вопрос, а не обязательно разрез;
- у некоторых границ цельный фрагмент пустой или очень короткий — это вариативность ASR/контекста, не доказанная ошибка.

Итоговая интерпретация: есть **статистически заметный эффект контекста** — отдельные halves расходятся с цельным проходом чаще, чем сами halves расходятся между повторными прогонами. Но этот тест не определяет, какой из двух выводов правилен. Без ручной эталонной транскрибации и прослушивания нельзя заявить, что 46% границ содержат ошибки, или что overlap даст такое же снижение WER. Чтобы установить долю именно ошибочных слов, следующий шаг — прослушать стратифицированную выборку из ~30 отмеченных и ~30 контрольных boundary WAV окон и вручную разметить reference; затем посчитать WER/KER и доверительные интервалы.

## Цена текущего лёгкого улучшения

Добавлен поиск низкоэнергетического 80 ms окна в радиусе ±1.5 s около границы, без сторонней модели/пакета. Буферы читаются по 20 ms для локальной оценки энергии, хранится только один короткий PCM буфер формата источника. К каждому чанку добавляется 0.75 s предыдущего аудио; теоретическая прибавка ASR-обработки для длинных записей около 3% длительности (дополнительные 0.75 s на каждые 24.25 s нового аудио), плюс малая цена чтения/энергетических вычислений. Замер реальной задержки и peak memory следует сделать на Mac после сборки Xcode.

Silero ONNX/CoreML здесь не добавлялся: его модельный размер, cold-start/RSS и время прохода не измерены на целевом Mac, поэтому нельзя обоснованно заявить их бюджет. Следующий этап — сравнить эту лёгкую схему с Silero на том же корпусе.
