# ТЗ: Компенсация деградации распознавания англоязычных IT-терминов в приложении «Голосок» (GigaAM v3 / macOS)

## 1. Цель проекта
Устранить систематические ошибки распознавания англоязычной технической лексики, названий утилит, сетевых протоколов и инструментов разработки (`Tailscale`, `OpenCode`, `Hindsight`, `Ollama`, `Vaultwarden`, `LLDP`, `SNMP`, `symlink` и др.) при сохранении сверхбыстрого инференса GigaAM v3 на Apple Silicon без существенного увеличения задержки (latency) и потребления памяти.

## 2. Архитектура решения (многоуровневая компенсация)
Система строится по принципу каскада (Defense-in-depth):
1. **Уровень 1 (In-engine Context Biasing / Hotwords):** Внедрение контекстного смещения декодера (Shallow Fusion / Aho-Corasick Hotwords) в рантайм ASR, чтобы модель на этапе лучевого поиска выбирала правильные BPE-последовательности терминов.
2. **Уровень 2 (Детерминированный словарь и Phonetic Replacer):** Локальная база сопоставлений паттернов искажений на Swift (0 мс задержки) с поддержкой регулярных выражений и пользовательского редактирования в UI настроек.
3. **Уровень 3 (AI Restoration Pipeline):** Фоновая/опциональная правка через `AIService` (локальная LLM через Ollama) со специализированным системным промптом восстановления code-switching.

## 3. Требования к компонентам

### 3.1. Модуль пользовательского словаря терминов (Term Dictionary & Rule Replacer)
* **Хранилище:** `terms_dictionary.json` в `Application Support/Golosok/`.
* **Формат записи:**
  ```json
  {
    "canonical": "Tailscale",
    "patterns": ["stale skale", "talescale", "тейлскейл", "тайлскейл"],
    "isRegex": false,
    "caseSensitive": false
  }
  ```
* **UI:** Новый раздел во вкладке «Настройки» («Словарь терминов и автозамена»):
  * Список терминов с возможностью добавления, редактирования, удаления.
  * Предустановленный набор базовых IT-терминов (OpenCode, Tailscale, Hindsight, Ollama, Docker, Kubernetes, Nginx, Swift, Python, GitHub, macOS и др.).
  * Тоггл «Включить автозамену терминов».
* **Интеграция:** Применение в пайплайне `AudioCapture.swift` сразу после получения сырого текста из CLI (`runCLIOnWav`).

### 3.2. ASR Engine Upgrade (Contextual Biasing / Sherpa-ONNX Hotwords)
* Поддержка передачи списка терминов непосредственно в процесс распознавания.
* Если используется сборка `sherpa-onnx` с моделью `gigaam-v3-rnnt`:
  * Передача аргументов `--hotwords-file=<path>` и `--hotwords-score=<float>` (подбор оптимального буста в диапазоне 1.5 – 3.0).
* Формирование актуального файла hotwords на лету из `terms_dictionary.json` перед вызовом CLI.

### 3.3. Специализированный пресет для AI-постобработки
* Добавление системного пресета в `prompts.json` с ID `restoreTechTerms`:
  * Задача: восстанавливать искажённые технические термины и транслит латиницей, не меняя структуру русской фразы и не добавляя комментариев.

## 4. Критерии приёмки
1. Запуск тестового прогона по выборке из 38 проблемных фраз из `history.json` (где встречались `stale skale`, `open-код`, `hinsite`, `simlink`, `абстрим`).
2. В результирующем тексте не менее 90% терминов приводятся к каноническому виду (`Tailscale`, `OpenCode`, `Hindsight`, `symlink`, `upstream`).
3. Дополнительная задержка (overhead) на этапе детерминированной обработки — не более 5 мс на фразу до 500 символов.
